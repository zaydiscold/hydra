# Hydra 1.6.1

Patch release. Fixes a ship-blocking schema bug in 1.6.0 and guards against it
recurring. **Anyone on 1.6.0 with an existing database should update to 1.6.1.**

## What changed

### Fix: missing migration for `User.authDisabled` (1.6.0 ship blocker)
1.6.0 added the `User.authDisabled` column to `prisma/schema.prisma` but shipped
**without a migration**. Dev passed because `prisma db push` builds the column
straight from the schema, but the packaged app heals schema by **replaying
migration SQL** (`server/lib/db-self-heal.js`) — `prisma db push` is dev-only.
With no migration to replay and no column in the bundled `empty-hydra.db`
template, both **fresh installs and upgrades-in-place** failed on first 1.6.0
boot:

```
[POOL] Rotation pool reloaded: 0 active key(s)
[AUTH] ... column main.User.authDisabled does not exist  (auth queries 500)
```

The fix adds the migration
`prisma/migrations/20260608000000_add_user_auth_disabled/migration.sql`
(`ALTER TABLE "User" ADD COLUMN "authDisabled" BOOLEAN NOT NULL DEFAULT false`),
which the self-healer applies idempotently to existing and template-based DBs.
Verified against a pre-1.6.0 database: after heal, the rotation pool reloads all
active keys and accounts/sessions are intact (no data touched).

### Guard: schema-migration coverage test
New `test:schema-migration-coverage` reproduces the real runtime path — copy the
`empty-hydra.db` template, run the migration self-healer, then assert every
scalar column in `schema.prisma` is present. A schema column with neither
template coverage nor a migration now fails CI (it pinpoints the exact
`Table.column`), so this class of bug can't ship again.

### Housekeeping
- `package-lock.json` version reconciled to match `package.json` (was stale at
  1.5.15).

## Verification

- `test:schema-migration-coverage` passes with the migration and fails (naming
  `User.authDisabled`) without it.
- Full `npm test` chain green on Node 26 (server + Electron).
- Cross-checked on the Windows device: 1.6.1 source synced, the migration heals
  the live 13-account database, rotation pool reloads 11 active keys, no schema
  or decrypt errors.
