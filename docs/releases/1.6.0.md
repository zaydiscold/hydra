# Hydra 1.6.0

Minor release adding two operator-facing features: a way to skip the splash
animation, and a unified way to turn the dashboard password off — interactively
or for headless deployments — without ever locking yourself out.

## What changed

### Splash hold-to-skip
- The splash screen now has a **Skip** control. Hold **Spacebar** (or
  press-and-hold the Skip pill) and a circular ring fills over **3 seconds**;
  at full, the splash dismisses early and the app opens immediately. Releasing
  before 3s smoothly resets the ring and the animation continues.
- The splash stays `focusable:false` (never steals OS focus on boot). Spacebar
  is captured via the splash `webContents` `before-input-event` and forwarded
  to a renderer `requestAnimationFrame` loop, so the 3-second hold is
  frame-rate independent. Skip reuses the existing splash teardown/reveal path —
  no parallel lifecycle. The matter.js physics, glyph sprite cache, and viewport
  culling are untouched.

### Unified disable-auth (env var + Settings toggle)
Two faces of one feature, both lockout-safe:
- **Deployment / headless:** `HYDRA_DISABLE_AUTH=1` bypasses the dashboard
  password so an always-on server (e.g. behind `tailscale serve → 127.0.0.1`)
  is reachable with no operator present. A loud SECURITY warning is logged at
  every boot. The `/v1` proxy still requires its master `sk-` key — unaffected.
- **Interactive / desktop:** a **Password Protection** toggle in Settings.
  Turning it **off** requires confirming your current password; afterwards Hydra
  opens straight in (the login screen is skipped). Turning it back **on**
  requires creating a **brand-new password**.
- **Lockout-safety:** disabling blanks the stored password hash to an unusable
  sentinel, and re-enabling always sets a fresh password. There is deliberately
  no "re-enable with the old password" path, so a forgotten disabled password
  can never lock you out.
- The middleware honors both signals — `HYDRA_DISABLE_AUTH` (env) **or** the
  persisted `User.authDisabled` flag (DB). A valid session always wins.

### Schema
- Added `User.authDisabled Boolean @default(false)`. Applied via `prisma db
  push` and the existing schema-hash self-heal; existing databases heal on boot
  with the column defaulting to `false` (no migration step for operators).

  lockout-safety proof that a disabled password is dead after re-enable) and the
