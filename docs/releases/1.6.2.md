# Hydra 1.6.2, fleet reliability and lighter operations

## What changed

- Sync now treats an explicit click as a recovery pass. It attempts silent renewal for stale, unknown, and errored sessions, not only a near-term expiry estimate.
- Session age is no longer presented as a known expiry. A stored age threshold now means **refresh due**, while **expired** is reserved for a definitive authentication rejection.
- Fixed a local high-cost-operation limiter that allowed twelve concurrent silent refreshes but rejected the thirteenth account in a fleet.
- Dashboard Sync now reports the time of the completed dashboard pass instead of an unrelated historical per-account timestamp.
- Code Redeemer loads from the hydrated Dashboard fleet if the narrow account list is temporarily empty, has a Reload control, shows selected-account readiness before execution, and remains a code-by-account matrix.
- Redemption results are now confirmation-strict: an unrecognised OpenRouter server-action response cannot turn a row green; it falls through to tRPC or browser verification. The UI, CLI, and history log only mark an explicit `success: true` as redeemed.
- Fleet redemption is paced and randomized: five accounts per wave, then a fresh 2–8 second jitter before the next wave. The assignment order is shuffled per run; the UI still reports each exact code/account outcome.
- CLI redemption is now direct for a fleet: `hydra codes redeem CODE --all --yes`. It runs a live preflight first and refuses the action if any selected account is not ready. Account selectors accept an ID prefix, alias, or email.
- `hydra serve --background` runs the local API and `/v1` proxy without Electron, follows the active runtime vault, writes logs to the data directory, and refuses to claim success if bootstrap exits immediately.
- Account Generator splits the reusable domain from the changing address name and remembers the domain locally.
- The account login modal is now clearer about its two routes: existing OpenRouter emails use a direct email code, while a new email is detected and handed to the browser-backed signup flow with the address prefilled. This matches OpenRouter's current interactive-verification requirement instead of presenting an OTP-only signup that cannot complete.
- Reduced splash load and idle visual weight: lower splash body budget and capped animation rates, calmer global shadows, and a dimmer background grid.

## Commands

```sh
# Confirm the fleet can use a code without applying it.
hydra codes preflight CODE --all

# Apply one code to every ready account, only after explicit confirmation.
hydra codes redeem CODE --all --yes

# Keep the proxy running without opening Electron.
hydra serve --background
```

Live code redemption deliberately requires an actual unused code and `--yes`; Hydra does not infer either. The safe preflight verifies local account-session readiness but does not submit a code.
